# Bounded Lua-signature scan, build 26136895

On the preserved snapshot, `cryo_probe scan-lua` searched every decoded entry returned by MIDA for the exact bytes `1b 4c 75 61` at any position in effective packages whose path contains `marathon_deck_001`. It reported 19 package IDs, 151,076 entries examined, zero decode errors, zero entries over its 64 MiB limit, and zero matches. `cryo-lua-scan.txt` contains per-package counts and the final totals; `cryo-lua-matches.jsonl` is empty. Effective patch resolution is MIDA's, not an independent decoder. The count is the API's returned entry count, not a claim that each is a unique meaningful object. The search does not cover other package families, encoded or encrypted nested content, Lua derivatives without the signature, or server files. An absence of this magic does not establish absence of script code.

This test was motivated by the local `tiger-research/packages/bullshcript/README.md`, which describes a decompiler for a specific Destiny 1 alpha bytecode format, not a Marathon-compatible decompiler. The next lead is the activity and pedestal native dispatch and build-specific metadata, not treating this narrow absence as proof that all scripts reside on a server.

Reproduce using the environment and build command in `2026-10-31-cryo-chain.md`, then replace the mode with `scan-lua`. No target game process or live service is contacted.
