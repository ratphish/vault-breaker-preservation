# Marathon → Sunrise/Dawn: Cross-engine Asset Import Research Handoff

**Research date:** 2026-10-27  
**Objective:** Evaluate the smallest reproducible, authorized, offline experiment for importing a Marathon static asset into the Destiny 2-based Sunrise/Dawn runtime, informed by the Destiny: Rising Haven demonstration.  
**Status:** Research and feasibility test plan; **not** a working Marathon converter.

## Executive decision

**Recommended path:** first establish a single-static-mesh interchange test via `Marathon decoded asset → interchange mesh/texture → Blender → Sunrise Studio original-static-prop import`. Do not commit to porting Cryo Archive, or conclude that Marathon logic can run in Dawn, until the mesh test succeeds and collision/material limitations are measured.

This is *not* evidence that the 2020 Destiny 2 executable understands Marathon's native 2026 tags. It is an interchange-and-reauthoring path into a different native package format. It avoids needing to port the full Marathon server to validate visual reuse, but still leaves gameplay semantics, animation, collision, weapon systems, AI, networking, and Vaultbreaker state logic unresolved.

## Important documented import constraints

From S2/S3, the original static-asset path accepts triangle meshes with normals, UVs, scene transforms, and supported PBR material subsets. The docs specify PNG images, one UV set, repeat wrapping, and backface culling. Studio maps base color, metallic/roughness and normal maps into existing game material slots. Unsupported elements include alpha masks/blending, emissive/occlusion textures, double-sided shaders, extra UV sets/texture transforms, many extensions, particles, skins, morph targets and animation **as authored static props**. A skinned mesh may be flattened by skip mode; that is not character animation support. glTF coordinates are converted Y-up ↔ Z-up.

**Reconstruction implications:** a high-quality map will also require authoring placements, LODs, collision, navmesh, materials, lighting, sky, triggers, playable boundaries, and entity behaviors. Static meshes are proof of rendering/import *only*.

## One bounded, concrete experiment (no bulk scanning)

**Preconditions:** legitimate local copies and tools; separate development environment, no changes to online Marathon or its anticheat; check project and asset licenses before redistribution.

1. **Inspect existing Vaultbreaker workspace** for an already decoded, small **static** Marathon mesh and its referenced texture(s). Do not launch a whole-package scan.
2. **Audit the extractors:** identify exact binary tag(s), build/version, decoding scripts, vertex/index layout, UV semantics, material IDs, and output format. Record what exists, not merely inferred class names.
3. **Choose one non-animated simple prop**, not a terrain tile, full room, character, or weapon. Prefer low material count and single UV set.
4. **Export a minimal interchange sample** as GLB with positions, triangle indices, normals, UV0, and optionally PNG textures. Keep an evidence log and deterministic conversion script. If geometry cannot be decoded, stop with an explicit blocker instead of inventing a successful import.
5. **Check Sunrise Studio's original-static-asset authoring profile** on a harmless, author-created control cube first to validate toolchain before adding source-asset complexity. Do not treat a source-free control-cube success as proof of Marathon compatibility.
6. **Attempt Marathon-derived GLB import** in an isolated offline Sunrise Studio project. Capture validation errors and transformed geometry/material state.
7. **If authorized and safe, test in an isolated Dawn environment**, without interfering with production services or anticheat. Verify presence, scale/orientation, mesh integrity, textures, rendering and basic placement; do not claim collision or gameplay success without tests.
8. **Stop and report** a reproducibility matrix: extracted tags and offsets, source build hash, conversion script, dimensions, screenshots, exact tool versions, import log, successful/failed properties, and next narrow task.

**Boundaries:** No full Cryo map conversion, no AI/gameplay reconstruction, no mass asset export, no bypassing security or online service controls, and no subagents. The original installed Marathon files remain unmodified.

## Decision gate

**Green:** author-created control cube imports, Marathon mesh decoding is reproducible, and a single prop imports and renders in an isolated environment. Then estimate whole-room work.

**Yellow:** package bytes available but asset geometry decoding incomplete, or Sunrise material import fails. Fix only the narrow blocker.

**Red:** converter depends on unshared private tooling, engine/runtime incompatibility, prohibited use, or unacceptable rights/anticheat risks. Fall back to independent original-asset recreation in Unreal without discarding the valuable vault gameplay specification.
